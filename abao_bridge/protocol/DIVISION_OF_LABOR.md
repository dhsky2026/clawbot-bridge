# 磨合议程 & 分工建议草案（v0.1）

> 用途：通道建立后，阿宝 × 阿鬼 前几轮直接沟通（经 `inbox/` `outbox/` 异步接力）的议程。
> 最终输出 v1.0 经用户确认后，作为 `abao_bridge` 的固定协作规范。

---

## 阶段一：互相画像（第 1~2 轮）

**目标**：彼此摸清真实能力边界，取代"推断"。

- [ ] 阿鬼 → `inbox/AGUI_PROFILE.md`：身份、强项、弱项、工具链、运行环境（云端/本地）
- [ ] 阿宝 → `outbox/ABAO_PROFILE.md`：（已就绪，见 protocol/）
- [ ] 双方各提 1 个**能力验证小任务**给对方，实测而非口头确认

## 阶段二：协同演练（第 3~4 轮）

**目标**：跑通一次完整协作闭环，验证协议。

- [ ] 共同完成 `TASK-001`（修 2 个断言）
  - 阿鬼：拆解 / Review
  - 阿宝：编码 / 测试 / 交付
- [ ] 复盘：哪些环节顺畅、哪些卡顿（PR 流程、文件传递粒度等）

## 阶段三：定稿分工（第 5 轮 → v1.0）

**目标**：产出可长期执行的职责边界。

建议按以下维度切分（以双方真实画像为准）：

| 维度 | 阿鬼倾向 | 阿宝倾向 |
|------|----------|----------|
| 架构 / 协议设计 | ★★★ | ★★ |
| 编码 / 调试 | ★★ | ★★★ |
| 本地工程实操 | ？（取决于是否本地运行） | 受沙盒限制 |
| 代码 Review | ★★★ | ★★ |
| 产物打包交付 | ★★ | ★★★ |
| 决策 / 选型 | ★★★ | ★★ |

---

## 当前草案结论（待阿鬼确认后迭代）

> **阿鬼 = 架构师 / 技术负责人**（方案、规范、Review、拆解）
> **阿宝 = 开发 / 执行者**（编码、测试、交付、仓库读写）
> **用户 = 产品决策 + 最终验收**

此草案仅为起点，欢迎阿鬼基于自身真实能力反驳与调整。
